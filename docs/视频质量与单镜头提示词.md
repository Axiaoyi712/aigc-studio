# 视频质量与单镜头提示词（v0.10.0）

## 已有首帧时的推荐路线

1. 打开镜头项目，选中并确认所需首帧。
2. 点镜头右侧“设为保稳基准”：使用 5.17 秒、种子 42、快速 8 步、固定机位与手部，只保留微表情、自然呼吸和已有台词。原动作文字继续保存。
3. 展开“生成前检查”，查看实际生成尺寸和最终提示词；检查对白、场景与首帧是否对应。
4. 点“用当前首帧生成视频”。若希望比较采样方案，改点“同首帧对比8／20步”。
5. 两种方案完成后点“查看视频对比”，比较清晰度、闪烁、手部、口型与声音，再采用合适版本。采用只调整本镜头的采样方案。
6. 动作稳定后，再选择“按动作描述生成”，逐步增加手部动作和小幅运镜。最后进行高清精修与成片导出。

## 全片资料与本镜头环境

“项目设定 → 环境使用方式”默认是“按镜头设置”。项目中的地点、时间、色调、光照和环境声继续作为全片规划资料保存，不会自动拼进每个镜头。统一画风仍会使用。

当前地点与光照可在“分镜设计 → 本镜头环境”填写；总提示词模式也会采用这组环境字段。留空时，视频以确认首帧的环境为准。生成新首帧时，可在画面描述中写清地点。

全片确实只在同一个环境时，可选择“全片同一环境”。此时项目环境字段成为共享默认值，镜头填写的环境优先覆盖。

## 提示词整理规则

- 总提示词非空时优先使用，不叠加左侧的旧动作、旧台词和旧运镜。
- 总提示词包含“首帧画面描述”和“动作、镜头与声音”等栏目时，两种描述分开使用。
- 总提示词为空时，视频动作正文优先；正文为空才使用左侧“动作与可见情绪”。
- “下一镜”“承接上一镜”等跨镜头衔接说明保留在编辑原文中，不提交给当前镜头。
- 同一句台词只提交一次，按 H3 的说话人编号及 `<d>[Chinese] 原文</d>` 结构整理，不翻译台词。已有完整 H3 格式也不会再次嵌套。
- 角色名称用作首帧身份标识；视频外观主要依据确认首帧，不再重复注入整份角色外观描述。
- 出现卡通角色的鼻翼、喉结等动作，或近景推进半米、动作堆叠时，显示检查建议。保稳模式会直接使用首帧姿态约束，原文不删除。

最终提交内容可以在每镜“生成前检查”展开、查看和复制；编辑保存后自动更新。

## 分辨率与时长

| 档位与时长 | 竖版原生生成尺寸 | 说明 |
| --- | --- | --- |
| 自适应高分辨率，3.04 秒 | 736×1280 | 约3秒为实验短片，低于当前节点主要训练时长范围 |
| 自适应高分辨率，5.17 秒 | 576×1024 | 为控制显存需求而降低原生尺寸，低于720p |
| 原生720p，3.04／5.17 秒 | 736×1280 | 横版1280×736、方形768×768；不支持更长时长或跟随首帧比例 |

原生720p档不会悄悄降分辨率。需要更长片段时，应拆分镜头，或主动改用自适应档。3.04 秒虽可执行，建议先以 5.17 秒验证口型与动作。

“拼接导出画布”只决定缩放和补边。“高清精修”使用后处理模型。两者都与 H3 的原生生成尺寸分别标示；2K首帧、1080p导出或提示词中的“8K”不会自动改变原生视频尺寸。

原生720p档已经过工作流参数与图形编译检查；8GB显卡的实际耗时、显存和画面稳定性仍需真实样片验证，建议一次生成一个短镜头。

## 同条件对比

对比使用同一确认首帧、同一提示词、时长、分辨率和种子。已填写种子时沿用，留空时固定为42。种子42仅用于可重复对比，不是更好画质的保证。

两种方案分别为8步加速LoRA和移除该加速LoRA的基础20步，串行运行。每段都会记录比较组、种子及生成快照。每次派发前再次检查首帧内容，图片改变时停止对应任务。

对比片不会自动替换已选用视频。完成后，在视频对比界面或视频版本下拉框选择采用。它们作为两个正常视频版本存入当前镜头目录，没有另外创建媒体备份。

这些改进处理提示词与规格冲突；生成质量仍需根据样片判断。高清精修不能修复错人物、错动作或突然换场景。

H3格式依据：[官方提示词指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)。
